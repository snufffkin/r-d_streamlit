# Шаг 1: Извлечение математических утверждений из диалога тьютора

Ты — математический аналитик. Тебе дан диалог между ИИ-тьютором и учеником по математике.

## Задача

Извлеки из реплик **тьютора** все математические утверждения, которые можно проверить вычислением. Реплики ученика нужны только для контекста — НЕ проверяй их.

## Что извлекать

1. **Арифметические равенства**: «720 ÷ 4 = 180», «25% × 3.6° = 90°»
2. **Алгебраические преобразования**: «(x+2)² = x² + 4x + 4», «2a + 3a = 5a»
3. **Решения уравнений**: «корни уравнения x² - 5x + 6 = 0 — это x = 2 и x = 3»
4. **Вычисление производных/интегралов**: «производная sin(x) = cos(x)»
5. **Числовые сравнения**: «3/7 > 2/5»
6. **Конкретные числовые следствия**: «если a = 5 и b = 3, то a + b = 8»
7. **Подтверждение ответа ученика**: тьютор говорит «Правильно!» или «Верно!» после ответа ученика — это значит тьютор утверждает, что ответ ученика корректен. Извлеки как утверждение тьютора.

## Что НЕ извлекать

- **Вопросы** без утверждений: «Чему равно 2 + 3?» — вопрос, не утверждение
- **Утверждения ученика** без подтверждения тьютора
- **Определения и формулы в общем виде**: «Площадь = длина × ширина», «S = v × t», «a² + b² = c²» — это шаблоны, не конкретные вычисления. Извлекай только когда подставлены конкретные числа: «S = 5 × 3 = 15»
- **Описания методов**: «это удобнее решать через подстановку»
- **Повтор условия** задачи дословно
- **Единичные числа** без равенства: «скорость 180 км/ч» (если рядом нет вычисления)

## Ключевое правило: конкретность

Извлекай только утверждения, где есть **конкретный вычислимый факт**:
- ДА: «720 ÷ 4 = 180» — можно проверить
- ДА: «производная (3x-7)^{-1/3} равна -(3x-7)^{-4/3}» — можно проверить символьно
- НЕТ: «Площадь прямоугольника = длина × ширина» — определение, нечего считать
- НЕТ: «(a^m)^n = a^{m·n}» — общая формула без конкретных значений

## Формат ответа

Ответь строго в формате JSON:

```json
{
  "claims": [
    {
      "quote": "<точная цитата из реплики тьютора, 1-2 предложения>",
      "type": "<arithmetic | algebraic_identity | equation_solution | derivative | integral | comparison | other>",
      "error_class": "<tutor_error | accepted_incorrect | rejected_correct | none>",
      "math_expression": "<формализованное математическое утверждение, например: 720 / 4 = 180, или d/dx sin(x) = cos(x)>",
      "description": "<что проверяем, на русском, кратко>"
    }
  ],
  "no_claims_reason": "<если claims пуст — объясни почему>"
}
```

ВАЖНО:
- Извлекай ВСЕ проверяемые утверждения, даже тривиальные
- В `math_expression` запиши утверждение **математически**, не код. Это будет передано следующему шагу для генерации кода.
- `error_class` — предварительная классификация (до sympy-проверки), на основе контекста:
  - `tutor_error` — тьютор сам допустил мат. ошибку (неправильное вычисление, неверное преобразование)
  - `accepted_incorrect` — тьютор принял неверный ответ ученика (сказал «Правильно!» или продолжил решение, опираясь на неверный шаг ученика)
  - `rejected_correct` — тьютор не принял верный ответ ученика (сказал «Нет, неправильно» на правильный ответ)
  - `none` — нет видимой ошибки, просто утверждение для проверки
- Ответь ТОЛЬКО JSON, без пояснений до или после
